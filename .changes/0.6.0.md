### Added

- **Review a branch with someone else's criteria (`skillFrom`).** `POST /api/review-branch` accepts `"skillFrom": "<username>"` (CLI: `review-branch --skill-from <username>`), so an author can check a branch against the designated reviewer's skill and severity/confidence thresholds before opening the MR. Only the skill and thresholds are borrowed: the engine, model, Claude token, language, limits, queue and the record stay the caller's. Any approved, enabled user can be named; the result reports `skill_from`, is kept separate from your own branch reviews and is never attached to an MR. `GET /api/branch-status` takes a matching `skill_from` parameter.
- `ARGUS_SKILL_FROM` (`on` by default) lets the operator turn the feature off; requests then get `403 skill_from_disabled`.

### Fixed

- Branch reviews find the ticket key in a lower-case branch name (for example `fix/proj-720-x`), so the requirement text reaches the review; version-like suffixes are skipped.
